# Phase 3 (aleph-cvm backport) Implementation Plan

> **For agentic workers:** This plan is executed via the proven Phase-2 port loop
> (decision 11): one increment = one stacked PR, implemented by a subagent, then a
> 3-lens adversarial review (parity / Rust robustness / CI-test quality), a
> consolidated fix batch with a regression test per finding, and merge on green. TDD
> happens *inside* each increment when the subagent reads the actual donor module.
> Increments are the reviewer-gate unit, per the writing-plans "Task Right-Sizing"
> rule.

**Goal:** Graft aleph-cvm's SEV-SNP confidential computing and NUMA capabilities onto
the completed Rust supervisor, foundation-first, without breaking the frozen gRPC
contract, the public CRN HTTP API, the existing SEV/SEV-ES flow, or zero-downtime
live-VM adoption.

**Architecture:** Rust first takes over the persistent-QEMU launch by porting the
thin Python per-VM controller into a Rust `aleph-vm-controller` binary that reads the
identical `{vm_hash}-controller.json` and emits a byte-identical QEMU argv (Stream A).
SEV-SNP and NUMA then graft on as argv fragments plus supervisor-side placement and an
attestation stack ported from aleph-cvm.

**Tech Stack:** Rust (tokio, tonic/prost, existing `supervisor-daemon`); a new Rust
controller binary in the `rust/` workspace; ported aleph-cvm crates `aleph-tee`,
`aleph-attest-agent`, `aleph-attest-cli`; aleph-cvm's Nix flake for the measured-boot
image; systemd (D-Bus + `AllowedCPUs`); QEMU + QMP; AMD SEV-SNP + `/dev/sev-guest`.

## Global Constraints

Copied verbatim; every increment's requirements implicitly include these.

- **Prose/comments/commits/PRs: no em-dashes.** Use commas, colons, or parentheses.
- **No `Co-Authored-By` trailer** in commits.
- **PR bodies end with:** `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- **Frozen gRPC contract:** `proto/supervisor.proto` already carries the SNP/NUMA
  fields (`TeeBackend::SEV_SNP`, `TeeConfig`, `ConfidentialMode::SEV_SNP`,
  `VmSpec.numa_node`, `HostInfo.numa_nodes`, `NumaNode`, `sev_snp_supported`). Populate
  and consume them; do not reshape existing messages.
- **Public CRN HTTP API unchanged**, including `/about/certificates`,
  `/about/capability`, and `/control/machine/{ref}/confidential/{initialize,
  measurement,inject_secret}`.
- **Existing SEV/SEV-ES launch-secret flow unchanged.** SNP is added alongside,
  backend-selected. Zero breakage.
- **Zero-downtime adoption preserved:** unit name `aleph-vm-controller@{hash}.service`
  and the controller-JSON contract stay stable; already-running VMs keep their current
  controller process until they cycle.
- **Parity oracle = the Python controller.** Port warts bug-for-bug unless dangerous;
  record any deliberate divergence in `docs/plans/rust-port-divergences.md`.
- **CI gates per increment:** `cargo fmt --check`, `cargo clippy -D warnings`,
  `cargo test`, the full Python suite, and the real-KVM Supervisor integration matrix
  (the leg that caught the sparse-tar bug). Confidential/NUMA paths without hardware in
  CI get unit tests + manual hardware checks (GPU-flow model, decision 10).
- **Every `Bash` call sets `dangerouslyDisableSandbox: true`** (git/cargo/systemd need
  it here).
- **Conformance harness extended every increment** (`tests/conformance/`), fixtures
  regenerated by the real Python code via `scripts/generate_rust_fixtures.py`.

## Stack shape

Each increment is a PR based on the previous increment's branch. Root is
`od/phase3-cvm-backport-design` (the design-doc commit `af33d88e`, on `origin/dev`).
SNP is front-loaded so the aleph-testnets attestation loop can begin as early as
possible (your directive: testnets runs once SEV-SNP is implemented). NUMA follows.

```
P0  design doc ...................... od/phase3-cvm-backport-design   (DONE, af33d88e)
A1  Rust controller, non-confidential od/phase3-a1-rust-controller
A2  Rust controller, SEV/SEV-ES parity od/phase3-a2-controller-confidential
A3  packaging cutover + integration .. od/phase3-a3-controller-cutover
B0  aleph-tee crate (report+KDS) ..... od/phase3-b0-aleph-tee

B1  SNP host launch + create path .... od/phase3-b1-snp-host-launch
B2b attest-cli verifier + secrets .... od/phase3-b2b-attest-cli
        --- SEV-SNP complete: start aleph-testnets SNP loop ---
C1  NUMA topology + cpuset pinning .... od/phase3-c1-numa-pinning
C2  NUMA memory binding + hugepages ... od/phase3-c2-numa-memory
        --- NUMA complete: add aleph-testnets NUMA scenario ---
```

Dependency note: **A1 blocks A2, B1, C2.** B0/B2a/C1 do not depend on Stream A and can
be reordered earlier if A stalls; they are stacked after A only because the stack is
linear. B1 needs A2 + B2a. B2b needs B0. V-SNP needs B1 + B2a + B2b.

## Stream A: Rust owns the persistent-QEMU launch (foundation)

The donor for *structure* is aleph-cvm's `aleph-compute-node/src/qemu/{args,process}.rs`,
but the argv **content** and the systemd model come from the Python controller (the
parity oracle), not aleph-cvm. We port the Python `QemuVM`, not aleph-cvm's builder.

### Task A1: Rust `aleph-vm-controller` binary, non-confidential path

**Files:**
- Create: `rust/crates/supervisor-controller/` (new binary crate `aleph-vm-controller`),
  with `src/main.rs` (arg parse `--config`, `--print-settings`, `-vv`, network wait,
  SIGTERM handler, dispatch), `src/config.rs` (read the JSON contract), `src/qemu.rs`
  (argv builder + spawn + graceful stop).
- Modify: `rust/Cargo.toml` (add the new workspace member).
- Test: `rust/crates/supervisor-controller/tests/argv_parity.rs`; conformance fixtures
  under `tests/conformance/controller_argv/`.
- Reference (do not port): Python `src/aleph/vm/hypervisors/qemu/qemuvm.py`
  (`QemuVM.start()`, the argv oracle), `src/aleph/vm/supervisor_interface/
  configuration.py` (`Configuration`/`QemuVMConfiguration`/`ControllerSettings`), and
  `packaging/aleph-vm/etc/systemd/system/aleph-vm-controller@.service`.

**Produces:** a `aleph-vm-controller --config={path}` binary that, for a
non-confidential persistent QEMU VM, reads `{vm_hash}-controller.json` and produces a
QEMU argv byte-identical to `QemuVM.start()`, spawns it, and shuts it down gracefully.

**Parity requirements (from the Python argv oracle, reproduce exactly):**
- Base: `-machine {q35 if gpus else pc}`, `-enable-kvm`, `-nodefaults`, `-m {mib}`,
  `-smp {vcpus}`, `-drive file={image},media=disk,if=virtio,file.locking=off`,
  `-display none`, `-monitor unix:{monitor_sock},server,nowait`, `-device virtio-serial`,
  QGA `-chardev socket,path={qga},server=on,wait=off,id=qga0` +
  `-device virtserialport,chardev=qga0,name=org.qemu.guest_agent.0`,
  `-qmp unix:{qmp},server,nowait`, `-serial stdio`, `-nographic`,
  `-boot order=c,reboot-timeout=1`.
- NIC only if `interface_name` set: `-device virtio-net-pci,netdev=net0,rombar=0` +
  `-netdev tap,id=net0,ifname={iface},script=no,downscript=no`.
- cloud-init only if `cloud_init_drive_path` set:
  `-drive file={iso},media=cdrom,readonly=on,if=virtio`.
- balloon only if no GPUs: `-device virtio-balloon-pci,free-page-reporting=on`.
- host volumes: per volume `-drive file={path},format=raw,readonly={on|off},media=disk,if=virtio`.
- no-GPU migration pin (note the deliberate *second* `-machine`, QEMU takes the last):
  `-machine pc-i440fx-6.2 -cpu host,migratable=on`.
- GPU args appended last: `-cpu host,host-phys-bits-limit=0x28` then per GPU
  `-device vfio-pci,host={pci_host},rombar=0[,x-vga=on]`.
- stdout/stderr → systemd journal streams tagged `vm-{vm_hash}-stdout` / `-stderr`.
- Graceful stop: QMP `system_powerdown` → wait 50s → QMP `quit` → wait 10s
  (`GRACEFUL_SHUTDOWN_TIMEOUT = 50`, coupled to unit `TimeoutStopSec=60`).
- Network pre-check: wait up to 120s for `vmtap{vm_id}` to appear; exit(1) if absent
  (do not create the tap in the normal path).

**Exit gate:** `argv_parity.rs` asserts byte-identical argv against Python-generated
fixtures for a battery (no-GPU, GPU, x-vga GPU, host-volumes, no-cloudinit, no-NIC).
`cargo test` + `fmt` + `clippy` green. Not yet wired into packaging (A3). Commit,
push, open PR based on `od/phase3-cvm-backport-design`.

### Task A2: Rust controller, SEV/SEV-ES confidential parity

**Files:**
- Modify: `rust/crates/supervisor-controller/src/qemu.rs` (add the confidential argv
  branch), `src/config.rs` (confidential fields `ovmf_path`, `sev_session_file`,
  `sev_dh_cert_file`, `sev_policy`), `src/main.rs` (dispatch: check the confidential
  config shape *before* the plain one, mirroring the Python `isinstance` ordering).
- Create: `rust/crates/supervisor-controller/src/cpuid.rs` (read
  `secure_encryption_info()` equivalent: SEV C-bit position + phys-addr reduction from
  host CPUID). Donor: aleph-cvm may already expose this; otherwise raw `cpuid`.
- Test: extend `argv_parity.rs` with confidential fixtures.
- Reference: Python `src/aleph/vm/hypervisors/qemu_confidential/qemuvm.py`
  (`QemuConfidentialVM.start()`).

**Consumes:** A1's argv builder + config reader.
**Produces:** the Rust controller launches an existing SEV/SEV-ES confidential VM with
argv byte-identical to `QemuConfidentialVM.start()`, paused (`-S`).

**Parity requirements (diffs vs A1 baseline):**
- OVMF pflash first: `-drive if=pflash,format=raw,unit=0,file={ovmf},readonly=on`.
- rootfs uses `format=qcow2` (no `file.locking=off`).
- `--no-reboot` present.
- `-S` (paused; CPU resumed externally after secret injection, not by the controller).
- `-object sev-guest,id=sev0,policy={sev_policy},cbitpos={cpuid},reduced-phys-bits={cpuid},dh-cert-file={godh},session-file={blob}`
  where `cbitpos` and `reduced-phys-bits` are derived at launch from host CPUID, not
  the JSON; `policy`/`dh-cert-file`/`session-file` from config.
- `-machine q35,confidential-guest-support=sev0`, `-cpu host,host-phys-bits-limit=0x28`.
- NIC without `rombar=0`. No balloon, no migration pin.
- Pre-launch: refuse if not on an AMD SEV platform, or if godh/session files missing.

**Exit gate:** confidential argv fixtures byte-match Python. `cargo test`/`fmt`/`clippy`
green. PR based on A1.

### Task A3: Packaging cutover + real-KVM integration

**Files:**
- Modify: `packaging/aleph-vm/DEBIAN/*` and the `Makefile` deb build to compile and

- Create/Modify: a controller-launcher analog to `packaging/supervisor-launcher` (or
  extend it) so `aleph-vm-controller@.service` `ExecStart` dispatches on

- Modify: `tests/integration/` — a test that boots a real non-confidential QEMU VM

  reaches RUNNING, serves, stops gracefully, and is re-adopted after a daemon restart.
- Reference: the existing `supervisor-launcher` dispatch and the Supervisor
  integration matrix job.

**Consumes:** A1 + A2.
**Produces:** on a `rust`-impl node, newly (re)started controller units run the Rust
controller; the daemon's existing `aleph-vm-controller@{hash}` adoption is unchanged
(the Rust controller reads the identical JSON, so both new and cycled-old VMs are
safe). Rollback = flip the flag to `python`.

**Exit gate:** the real-KVM integration leg boots and tears down a QEMU VM under the
Rust controller, and re-adopts it across a daemon restart, both impls green in the
matrix. **After A3, Rust owns the persistent-QEMU launch.** PR based on A2.

## Validation: aleph-testnets

Runs in the `aleph-testnets` repo (harness branch `od/aleph-vm-upgrade-checks`,
push-triggered, never-merge), not as an aleph-vm PR. Consent for testnets runs is
granted for this program.

### V-SNP (starts after B2b)

Because in-protocol scheduling is deferred (design §6), the harness does not create the
SNP VM from an Aleph `instance` message. It:
1. Installs the candidate aleph-vm deb (`ALEPH_VM_SUPERVISOR_IMPL=rust`) on a
   **SEV-SNP-capable host** (provisioning that host is a prerequisite, design §9, not
   the default droplet).
2. Builds/pulls the B2a Nix measured image (OVMF + kernel + initrd + attest-agent).
3. Calls supervisor gRPC `CreateVm` **directly** with
   `TeeConfig{backend: SEV_SNP, firmware_path: measured_ovmf}` and the image.
4. Runs `aleph-attest-cli attest --url {vm} --expected-measurement {precomputed}` and
   asserts: the embedded SNP report validates against the AMD KDS chain during the TLS
   handshake, and the measurement matches the Nix precomputed value.
5. `fresh-attest` with a random nonce; assert the nonce appears in `report_data`.

### V-NUMA (starts after C2)

On a multi-node host where available: create two VMs via gRPC pinned to distinct nodes,
assert `VmInfo.numa_node` reflects placement, `AllowedCPUs` matches the node cpuset,
and (where observable) memory is bound to the node.
